## Role

This component executes WASM smart-contract code for the `FunctionCall` action. It is invoked by the runtime ([runtime-execution](runtime-execution.md)) once per executed function call: the runtime builds a `GasCounter` and calls `prepare` (`runtime/runtime/src/pipelining.rs:441` — `prepare_function_call`), then `run` with a `VMContext`, the `RuntimeFeesConfig` and an `External` trait object that proxies trie reads/writes and receipt creation (`runtime/runtime/src/function_call.rs:233` — `execute_function_call`, calling `near_vm_runner::run` at `:281`). The VM validates and instruments the WASM (`prepare_contract`), compiles it with wasmtime, links it against the host-function (bindings) ABI, meters every WASM op and host call against a gas counter, and runs the requested entry point. Host calls let the contract read/write contract storage (delegated to [state-storage](state-storage.md)), read context/economics, compute hashes/signatures, and **create promises** that the runtime turns into receipts handled by [cross-shard-congestion](cross-shard-congestion.md). The result is a `VMOutcome` (burnt/used gas, compute usage, logs, return data, and an optional `aborted` guest error). Execution must be a deterministic pure function of its inputs: gas and outcome must be byte-identical on every validator (`runtime/near-vm-runner/src/runner.rs:25` — `VMResult` doc comment). Out of scope: how the runtime drives the `FunctionCall` action loop and distributes unused gas → [runtime-execution](runtime-execution.md); the trie itself → [state-storage](state-storage.md).

**This release removed the NearVM backend entirely** (#15988, #15989: the whole `runtime/near-vm*` engine crate tree, ~245k lines). Wasmtime is the only VM. The legacy `VMLogic` struct was also deleted (#16322): host functions are now free functions over a wasmtime-specific `Ctx`. See §1 and §6.

## Behavior

### 1. VM backend selection — Wasmtime only

`VMKind` comes from `Config::vm_kind`, populated from the versioned parameter table (`core/parameters/src/parameter_table.rs:450` — `vm_kind: params.get(Parameter::VmKind)?`). The base value is `Wasmer2` (`core/parameters/res/runtime_configs/parameters.yaml:327`) and the last override is at protocol version 84: `vm_kind: { old: "NearVm", new: "Wasmtime" }` (`core/parameters/res/runtime_configs/84.yaml:2`). Since `MIN_SUPPORTED_PROTOCOL_VERSION` is 84 (`core/primitives-core/src/version.rs:652`), **every supported protocol version resolves to `Wasmtime`**.

`VMKindExt::runtime` (`runtime/near-vm-runner/src/runner.rs:214`) has exactly one arm, `Self::Wasmtime => WasmtimeVM::new(config)` under `#[cfg(feature = "wasmtime_vm")]`; every other kind falls through to `None`. `VMKindExt::is_available` (`:205`) returns `false` for `Wasmer0`, `Wasmer2` and `NearVm` unconditionally. The public wrappers `prepare` (`:54`), `run` (`:89`), `contract_cached` (`:27`), `precompile_contract`/`try_precompile_contract` (`runtime/near-vm-runner/src/cache.rs:1072`/`:1096`) resolve the runtime with `unwrap_or_else(|| panic!("the {vm_kind:?} runtime has not been enabled at compile time or has been removed"))` — i.e. a config naming any other kind is a hard node-level panic, not a protocol outcome.

`VMKind::replace_with_wasmtime_if_unsupported` (`core/parameters/src/vm.rs:42`) still forces `Wasmtime` on non-x86_64 when parsing the parameter (`core/parameters/src/parameter_table.rs:239`); at every supported version this is a no-op because the parsed value is already `Wasmtime`.

**Engine configuration and determinism.** One `WasmtimeVM`/`Engine` is cached per `(Config, target)` in a process-wide map (`runtime/near-vm-runner/src/wasmtime_runner/mod.rs:81` — `VMS`; `:447` — `new_for_target`). The engine is configured (`:481`–`:546`) with: pooling allocation bounded by `MAX_CONCURRENCY = 1_000` (`:47`) core instances/memories, `max_core_instance_size(MAX_CORE_INSTANCE_SIZE)` = 1 MiB of per-instance runtime metadata (`:73`, `:494`), `table_elements`/`max_tables_per_module` from `LimitConfig`, backtraces and address maps disabled, `memory_init_cow`, `max_wasm_stack(1 GiB)` (stack metering is done by instrumentation instead), NaN canonicalization on, signals-based traps, and a fixed memory reservation so bounds checks can be elided. The compilation **strategy is `Winch` on x86_64 and `Cranelift` elsewhere** (`:520`), because Winch on aarch64 lacks wide-arithmetic in wasmtime 45. Two different compilers can differ in observable trap/behavior corners, which is why `neard` refuses to start a mainnet/testnet validator on a non-x86_64 host (`neard/src/cli.rs:392` — `check_validator_arch`, panics with "running a … validator on the … architecture is not supported; validators must run on x86_64").

### 2. Contract preparation (`prepare_contract`)

`prepare::prepare_contract` (`runtime/near-vm-runner/src/prepare.rs:21`) builds a `WasmFeatures` from the config and delegates to `prepare_v3::prepare_contract` (`runtime/near-vm-runner/src/prepare/prepare_v3.rs:402`). `prepare_v2` was deleted this release (#16355); `prepare_v3` is the only path, and the old wasmparser version was dropped (#16052) — validation now runs on `finite_wasm_6::wasmparser` only.

Enabled wasm features are a fixed allow-list (`runtime/near-vm-runner/src/features.rs:41`): floats, mutable globals, sign extension and saturating float-to-int are always on; reference types and bulk memory follow `config.reftypes_bulk_memory` (on since PV 84); multi-value, SIMD, threads, tail calls, multi-memory, memory64, exceptions, GC, component model, function references, wide arithmetic and custom page sizes are all off (`runtime/near-vm-runner/src/features.rs:7`–`:24`). Note the engine itself is built with `wasm_wide_arithmetic(true)` (`wasmtime_runner/mod.rs:548`); that is harmless because validation already rejected such modules.

Preparation is a single streaming pass (`PrepareContext::run`, `prepare_v3.rs:62`) that validates, rewrites and limits the module, followed by instrumentation:

1. **Limits decremented per section** — each limit is a counter subtracted with `checked_sub`, so overflow is the error: types → `TooManyTypes` (`:86`), tables → `TooManyTables` (`:116`) and per-table `initial > max_elements_per_contract_table` → `TooManyTableElements` (`:122`), **globals → `TooManyGlobals` (`:149`)** (new this release, #16047; the parameter `max_globals_per_contract` is only set at nightly 157 so at 87 the limit is `u64::MAX`), functions → `TooManyFunctions` (`:235`), locals → `TooManyLocals` (`:259`).
2. **Locals limit is code-size dependent** (new this release, #16348). `max_locals` (`:464`) takes the **minimum** of the absolute `max_locals_per_contract` and `code.len() / min_contract_size_per_local`. `min_contract_size_per_local` is set to `2` at PV 87 (`core/parameters/res/runtime_configs/87.yaml:11`), so a contract gets at most one local per two bytes of source, *in addition to* the absolute cap of 1,000,000 locals set at PV 53 (`core/parameters/res/runtime_configs/53.yaml:14`). Asserted by `locals_limit_depends_on_contract_size` (`runtime/near-vm-runner/src/prepare.rs:55`).
3. **Memory is normalized.** Any internal memory section is dropped and replaced with a single memory of exactly `initial_memory_pages`..`max_memory_pages` (`:352` — `ensure_memory_section`, `:376` — `memory_type`, emitted at `:136` and `:357`). An *imported* memory is rejected outright (`:327` — `TypeRef::Memory(_) => PrepareError::Memory`), as are imported tables, globals and tags (`:325`–`:328`). Imports from any module other than `env` are `PrepareError::Instantiate` (`:316`), and each function import consumes one unit of the function budget (`:322`).
4. **Exports are prefixed.** Every export name is rewritten with `EXPORT_PREFIX` = `"\0"` (`runtime/near-vm-runner/src/lib.rs:48`, applied at `prepare_v3.rs:163`), so guest exports can never collide with the host-injected `memory`/`remaining_gas`/`start` names.
5. **Per-function body size** above `max_function_body_size` → `FunctionBodyTooLarge` (`:250`), then full `wasmparser` function validation (`:274`).
6. **Custom sections** are dropped when `discard_custom_sections` is set (`:278`). Any unknown/unsupported section (component model, tags, module linking, …) → `Deserialization` (`:300`).
7. **finite-wasm analysis + instrumentation** (`:410`–`:449`): `finite_wasm_6::Analysis` computes gas and max-stack annotations using `regular_op_cost`/`linear_op_base_cost`/`linear_op_unit_cost`, then `InstrumentContext::run` injects the metering calls into the `internal` module (so contracts cannot call them through `env`) and enforces `max_blocks_per_function` → `TooManyBlocksPerFunction`, `max_blocks_per_contract` → `TooManyBlocksPerContract`, `max_params_per_function`/`_per_contract` → `TooManyParams*`, `max_operand_stack_bytes_per_function` → `OperandStackTooLarge`.
8. **Instrumented size cap** (`:455`): if the instrumented output exceeds `max_instrumented_code_size` (16 MiB since PV 84) → `InstrumentedCodeTooLarge`, guarding Cranelift's 24-bit SSA counter.

All failures are `PrepareError` variants (`runtime/near-vm-runner/src/logic/errors.rs:163`), wrapped by the caller into `CompilationError::PrepareError`. Preparation is **not** separately gas-costed: it runs inside `compile_uncached` (`runtime/near-vm-runner/src/wasmtime_runner/mod.rs:570`), i.e. once per cache miss rather than once per call, and the only load-related fee is the contract-loading fee of §3.

### 3. Compile, load, and the contract-loading fee

`WasmtimeVM::compile_uncached` (`runtime/near-vm-runner/src/wasmtime_runner/mod.rs:570`) runs `prepare_contract` then `engine.precompile_module`; a wasmtime failure becomes `CompilationError::WasmtimeCompileError`. `compile_and_cache` (`:609`) uses double-checked locking against a per-code-hash `CompilationLockMap` (`:91`) so concurrent apply/witness-validation threads never compile the same contract twice; `try_compile_and_cache` (`:635`) returns `Ok(None)` instead of blocking, for opportunistic background warming. Both funnel into `compile_and_persist` (`:657`), which stores either `CompiledContract::Code` or `CompiledContract::CompileModuleError` in the cache.

`with_compiled_and_loaded` (`:686`) resolves the artifact and charges the loading fee. Ordering is load-bearing:

1. Compute the `ContractCacheKey`, `touch` it, and look it up in the in-memory `AnyCache`; on a miss consult the on-disk cache; on a miss there, `contract.get_code()` (absent ⇒ `VMRunnerError::ContractCodeNotPresent`) and `compile_and_cache`.
2. `unsafe { Module::deserialize(&self.engine, &module) }` (`:747`). **On failure the behavior is protocol-gated** (`:753`): if `config.fix_contract_loading_error` is set, the failure is cached and returned as `FunctionCallError::LoadingError { msg }`, so it flows through the fee-charge points below and finalizes as a *gas-bearing* `abort`; otherwise it returns `Err(VMRunnerError::LoadingError(..))`, which the runtime converts into a zero-gas `VMOutcome::nop_outcome` (`runtime/runtime/src/function_call.rs:331`). See §Protocol-version-gated behavior.
3. Resolve the `memory` export (missing ⇒ `FunctionCallError::LinkError { msg: "memory export missing" }`, `:764`), record the optional `remaining_gas` and `start` export indices, build a `Linker`, `link` the host functions (`:1140`), and `instantiate_pre`. Every one of these failures is cached as a `FunctionCallError`, not as a hard error.
4. `gas_counter.before_loading_executable(config, method, wasm_bytes)` (`runtime/near-vm-runner/src/logic/gas_counter.rs:235`): reject an empty `method_name` with `MethodResolveError::MethodEmptyName`; then, **only if `fix_contract_loading_cost`**, pre-charge `add_contract_loading_fee` (= `contract_loading_bytes * code_len` then `contract_loading_base`, `:224`), mapping out-of-gas to `HostError::GasExceeded`. Failure here becomes `PreparationResult::OutcomeAbort`.
5. If the artifact resolved, `gas_counter.after_loading_executable(config, wasm_bytes)` (`:259`) charges the same fee **only if `fix_contract_loading_cost` is not set** — the legacy post-load ordering, which is what runs on stable at PV 87 (`fix_contract_loading_cost` is nightly-only, PV 129).
6. Then `prepare` (`:891`) resolves the method export by its prefixed name `"\0{method}"`: a missing export → `MethodResolveError::MethodNotFound` and a non-`() -> ()` signature → `MethodResolveError::MethodInvalidSignature`, both recorded as `PreparationResult::OutcomeAbortButNopInOldProtocol`.

### 4. Run (`PreparedContract::run`)

`run` (`runtime/near-vm-runner/src/wasmtime_runner/mod.rs:996`) turns the `PreparedContract` into a `VMOutcome`:

1. Build `ExecutionResultState::new` (`runtime/near-vm-runner/src/logic/logic.rs:45`) — panics if `account_balance + attached_deposit` overflows `u128`.
2. If preparation produced `OutcomeAbortButNopInOldProtocol`/`OutcomeAbort`, return immediately via `abort_but_nop_outcome_in_old_protocol`/`abort` (`:1007`/`:1010`).
3. Transmute `ext`/`context` to `'static` (safe only because they outlive the call), build the `Ctx`, and create the `Store`; install the store limiter.
4. Acquire a concurrency permit from the `ConcurrencySemaphore` (`:1025`); failure ⇒ `LinkError { msg: "failed to acquire execution slot" }` as a graceful abort.
5. `pre.instantiate(&mut store)`; failure ⇒ `abort` with the mapped error (`:1032`). Then eagerly resolve the real post-instantiation `memory` export (`:1048`), avoiding a wasmtime panic path for host-trampoline callers.
6. If the module exports `remaining_gas`, install a `store.call_hook` (`:1060`): on `CallingHost`/`ReturningFromWasm` it burns `gas_counter.remaining_gas() - global` into the counter; on `ReturningFromHost`/`CallingWasm` it re-publishes `remaining_gas()` into the global. This is how inline-metered wasm gas reaches the `GasCounter`.
7. Run the optional `start` export, then the resolved method via `call` (`:976`). A method missing at call time yields `RunOutcome::AbortNop`.
8. Map the result (`:1099`): `Ok ⇒ VMOutcome::ok`, `AbortNop ⇒ abort_but_nop_outcome_in_old_protocol`, `Abort ⇒ abort`. The `Ctx` is destructured out of the store first, because building the outcome consumes the `ExecutionResultState` that lives inside it.

Wasmtime errors are classified by `IntoVMError for wasmtime::Error` (`:373`): a host error carried in an `ErrorContainer` is unwrapped back into `HostError`/`ExternalError`/`InconsistentStateError`; a `wasmtime::Trap` is mapped through `TrapClassification` to a `WasmTrap` variant, except that `Interrupt`/`HeapMisaligned` become `VMRunnerError::Nondeterministic` (`:414`), any other trap becomes `VMRunnerError::WasmUnknownError` (`:408`), and a trap that should be impossible under NEAR's engine configuration `panic!`s outright (`:402`).

### 5. Gas metering

Two categories, both through `GasCounter`:

- **WASM instruction cost.** finite-wasm instrumentation calls into the `internal` module: `finite_wasm_gas` (`runtime/near-vm-runner/src/wasmtime_runner/logic.rs:186`) burns a precomputed gas amount; `linear_gas` (`:190`) backs the bulk memory/table variants (`finite_wasm_memory_copy`/`_fill`/`_init`, `finite_wasm_table_copy`/`_fill`/`_init`, `:197`–`:255`) as `constant + count * linear`. `finite_wasm_stack` (`:257`) decrements `ctx.remaining_stack` by `operand_size + frame_size` (underflow ⇒ `MemoryAccessViolation`) and charges `ceil(frame_size/8) * regular_op_cost`; `finite_wasm_unstack` (`:273`) restores it. `finite_wasm_gas_exhausted` (`:286`) burns all remaining gas and returns `IntegerOverflow`; `finite_wasm_stack_exhausted` (`:294`) returns `MemoryAccessViolation`. The legacy `gas` import is still exposed and maps to `gas_seen_from_wasm` → `gas_opcodes` (`:2215`, `:2196`), charging `opcodes * regular_op_cost`.
- **Host-function `ExtCosts`.** Every host fn starts with `pay_base(base)` and then pays its own `pay_base`/`pay_per` costs (`runtime/near-vm-runner/src/logic/gas_counter.rs:305`, `:290`); both update the profile with the gas actually burnt, even when the charge fails. Reading an argument charges `read_memory_base/_byte` or `read_register_base/_byte` depending on whether `len == u64::MAX` (`wasmtime_runner/logic.rs:138` — `get_memory_or_register`); writing a result charges `write_memory_*`/`write_register_*`. Action-shaped costs go through `pay_action_accumulated` (`gas_counter.rs:322`), which also accumulates `send_action_compute_usage` (falling back to the burnt gas when the charge hit a limit, for backwards compatibility).

**Burnt vs. used.** `burn_gas` (`gas_counter.rs:155`) adds to `fast_counter.burnt_gas` and fails if it would exceed `fast_counter.gas_limit`. `deduct_gas(burnt, used)` (`:126`) moves `used - burnt` into `promises_gas` (gas reserved for prepaid promise execution) and shrinks `gas_limit` to `min(max_gas_burnt, prepaid_gas - promises_gas)` (`:139`). `used_gas = promises_gas + burnt_gas` (`:384`); `remaining_gas = prepaid_gas - used_gas` (`:389`). On a limit crossing, `process_gas_limit` (`:176`) clamps burnt to `min(prepaid_gas, max_gas_burnt)`, saturates `promises_gas`, and returns `GasLimitExceeded` if `max_gas_burnt` was crossed, else `GasExceeded` — preferring `GasLimitExceeded` for compatibility.

**View calls are bounded by `max_gas_burnt_view`** (new this release, #16130). `GasCounter::new` (`:85`) now sets `prepaid_gas = max_gas_burnt` when `is_view` (`:101`), instead of widening it to `Gas::MAX`. The comment at `:93` explains why: `remaining_gas()` seeds the in-wasm gas global on the wasmtime backend, so a `Gas::MAX` seed let a pure-wasm loop with no host imports run until it drained ~`u64::MAX` of guest gas before the cap was ever checked. Promises are prohibited in view mode, so `used_gas` never exceeds `burnt_gas` and no view-call result changes. The runtime supplies `max_gas_burnt` from `ViewConfig` when present, else `limit_config.max_gas_burnt` (`runtime/runtime/src/pipelining.rs:426` — `PipelineManager::gas_counter`).

`compute_outcome` (`runtime/near-vm-runner/src/logic/logic.rs:110`) folds the wasm-instruction cost into the profile and computes `compute_usage` via `total_compute_usage` (NEP-455 compute costs), decoupled from gas.

### 6. Host-function (bindings) API

The import table is declared once by the `imports!` macro (`runtime/near-vm-runner/src/imports.rs:96`), which expands to `for_each_available_import!(config, M)` — a macro that emits an import **only if its `Config` boolean gate is true** (`:75`), so a host function is literally absent from the linker namespace before its activation version. `link` (`runtime/near-vm-runner/src/wasmtime_runner/mod.rs:1140`) walks that list and `func_wrap`s each name into the `Linker`, wrapping every host error in an `ErrorContainer` so it survives the trip through wasmtime.

**`p256_verify` accepts high-s signatures** (documented this release, #16026). ECDSA signatures are malleable — if `(r, s)` verifies so does `(r, n - s)` — and `p256_verify` deliberately accepts both, delegating to a FIPS 186-5 compliant implementation without low-s normalization, because WebAuthn does not require low-s and real authenticators (notably Apple's Secure Enclave) emit high-s signatures (`wasmtime_runner/logic.rs:1989`–`:2007` doc block). Unlike `ecrecover` it takes no malleability flag. Callers that use signature bytes for replay protection must normalize themselves. Pinned by `test_p256_verify_wycheproof_high_s_accepted`; changing it would be protocol-breaking.

#### 6.1 Promises → receipts

`promise_batch_create` (`:2455`) reads and parses the target account, charges `pay_gas_for_new_receipt` (`:2244` — `new_action_receipt` send+exec, plus `new_data_receipt_base` for each data dependency), calls `ext.create_action_receipt`, and pushes a `Promise::Receipt`. `promise_batch_then` (`:2504`) additionally wires the new receipt's data dependencies to the receipts behind `promise_idx`. `promise_create` (`:2285`) / `promise_then` (`:2331`) are convenience wrappers over the batch pair plus a function-call action, and therefore charge `base` twice (documented at `:2284`). `promise_and` (`:2385`) builds a `Promise::NotReceipt` joining several promises' receipt sets. `checked_push_promise` (`:520`) enforces `max_promises_per_function_call_action` with `NumberPromisesExceeded`. `promise_idx_to_receipt_idx_with_sir` (`:2598`) resolves a promise index to a receipt index and the "same-in-receiver" flag used to pick send-fee rates, rejecting joint promises.

Batch actions (`:2630`–`:4038`): `create_account`, `deploy_contract`, `deploy_global_contract` / `_by_account_id`, `use_global_contract` / `_by_account_id` (all four gated by `global_contract_host_fns`), `state_init` / `_by_account_id` (`:2990`/`:3030`) with `set_state_init_data_entry` (`:3100`), `function_call` (`:3324`) and `function_call_weight` (`:3385`), `transfer` (`:3489`), `transfer_to_gas_key` (`:3549`), `add_gas_key_with_full_access` (`:3618`) / `_with_function_call` (`:3686`) (gated by `gas_key_host_fns`), `stake` (`:3791`), `add_key_with_full_access` (`:3840`) / `_with_function_call` (`:3893`), `delete_key` (`:3989`), `delete_account` (`:4038`). There is deliberately **no** batch action for `WithdrawFromGasKey` (`runtime/near-vm-runner/src/imports.rs:312` comment, NEP-611): actions that reduce a gas-key balance must originate from transactions so the pending-transaction queue can see them. `promise_set_refund_to` (`:2559`) redirects failure refunds for a promise.

**Universal accounts (new at 87).** Two host functions gated by `config.universal_accounts`: `universal_state_init_to_account_id` (`:3181`, #16307) hashes the caller-supplied borsh `UniversalStateInit` bytes with SHA3-256 and writes the `0u` account id via `encode_universal_account_id` into a register — it inspects nothing, so any byte string maps to some id; and `promise_batch_action_universal_state_init` (`:3245`, #16308) appends a `UniversalStateInit` action carrying those exact bytes. The size terms are charged *before* the payload is decoded and the content terms as soon as the counts are known, both before the action exists, so a failed charge never leaves a half-priced action on the receipt (`:3268` comment; `pay_universal_state_init_terms` `:3296`). It deliberately does not check that the promise receiver matches the derived id — that check belongs to the receipt's own validation. See [runtime-execution](runtime-execution.md) for the action itself.

**Yield/resume**: `promise_yield_create` (`:4113`), `promise_yield_create_with_id` (`:4198`), `promise_yield_resume` (`:4341`), `promise_yield_resume_with_yield_id` (`:4390`); the `_with_id`/`_with_yield_id` pair is gated by `yield_with_id_host_fns` (PV 85). **Results**: `promise_results_count` (`:4451`), `promise_result` (`:4484`), `promise_return` (`:4527`, a joint promise ⇒ `CannotReturnJointPromise`). The receipt objects and their cross-shard delivery belong to [runtime-execution](runtime-execution.md) / [cross-shard-congestion](cross-shard-congestion.md).

### 7. Compiled-contract caching

The cache key `ContractCacheKey::Version5` (`runtime/near-vm-runner/src/cache.rs:44`) hashes `code_hash`, `Config::non_crypto_hash()`, `vm_kind`, and the backend `vm_hash` (`get_contract_cache_key`, `:53`), so any config or engine change invalidates every entry. `WasmtimeVM::vm_hash` (`runtime/near-vm-runner/src/wasmtime_runner/mod.rs:558`) mixes `engine.precompile_compatibility_hash()` with a manually bumped `version` (currently 73). `config_cache_key_signature` (`cache.rs:76`) exposes the same hash minus the code hash, so two configs can be compared for cache compatibility without enumerating the inputs.

Two levels: a per-cache in-memory `AnyCache` of loaded `PreparedModule`s (`cache.rs:947` — `AnyCache`, an LRU bounded both by item count and by an estimated weight; sized in `FilesystemContractRuntimeCache::with_memory_cache` at `:414` assuming ~16 MiB per contract), and an on-disk `FilesystemContractRuntimeCache` (`:300`) storing serialized executables or a `CompileModuleError`, with a byte-bounded LRU over the directory built by `build_disk_index` (`:542`) and refreshed via throttled atime updates (`:486`). The stored `CompiledContractInfo.wasm_bytes` carries the source size so the loading fee can be charged without re-reading the source.

`precompile_contract` (`:1072`) warms the cache; `try_precompile_contract` (`:1096`) is its non-blocking variant for background warming. **The `on_protocol_version_update` sweep was removed this release** (#15988) — `FilesystemContractRuntimeCache` no longer overrides it, so the trait's no-op default applies (`:146`). Stale artifacts are now simply never hit, because the config change moves the cache key.

## Interactions

- **Invoked by** the runtime for the `FunctionCall` action: `prepare_function_call` (`runtime/runtime/src/pipelining.rs:441`) builds the `PreparedContract` ahead of time, `execute_function_call` (`runtime/runtime/src/function_call.rs:233`) builds the `VMContext` and calls `run`, and the runtime consumes the `VMOutcome` (including distributing unused gas to weighted function calls) → [runtime-execution](runtime-execution.md).
- **Emits promises** that the runtime materializes as action/data receipts, then routed and throttled by [cross-shard-congestion](cross-shard-congestion.md).
- **Storage host calls** delegate to `ext: dyn External` (`runtime/near-vm-runner/src/logic/dependencies.rs:87`) → [state-storage](state-storage.md); `storage_get_mode` selects flat-storage vs. trie reads.
- **Recorded storage proof** feeds stateless validation; the per-receipt bound is seeded by the runtime (`runtime/runtime/src/lib.rs:925`) and enforced here → [stateless-validation](stateless-validation.md).
- **Costs** (`ExtCosts`, `ActionCosts`, wasm op costs, VM limits) come from the versioned parameter table → [economics](economics.md), [genesis-configuration](genesis-configuration.md).

## Protocol-version-gated behavior

`STABLE_PROTOCOL_VERSION` = 87 (`core/primitives-core/src/version.rs:680`), `MIN_SUPPORTED_PROTOCOL_VERSION` = 84 (`:652`), `NIGHTLY_PROTOCOL_VERSION` = 157 (`:683`). Activation versions come from `ProtocolFeature::protocol_version` (`:500`); `ProtocolFeature::enabled` is at `:643`.

Note that **not every VM behavior change has a `ProtocolFeature` variant**. Several are pure runtime-config flags flipped in a versioned parameter diff, with no enum entry: the parameter table is itself versioned, so flipping a flag in `core/parameters/res/runtime_configs/<N>.yaml` is a complete activation mechanism.

### Gated by a `ProtocolFeature`

- **`FixContractLoadingError`** — activates **PV 87** (`core/primitives-core/src/version.rs:619`); new this release (#15923, #16315). Sets `Config::fix_contract_loading_error` (`core/parameters/res/runtime_configs/87.yaml:28`). When a compiled module fails to load at `Module::deserialize`, the failure is now cached and returned as `FunctionCallError::LoadingError` (`runtime/near-vm-runner/src/wasmtime_runner/mod.rs:753`), which flows through `before_loading_executable`/`after_loading_executable` and finalizes as a **gas-bearing abort** that charges the contract-loading fee. Before 87 the same failure returned `VMRunnerError::LoadingError`, which the runtime turned into a **zero-gas nop outcome** (`runtime/runtime/src/function_call.rs:331`). **Distinct from `FixContractLoadingCost`** (below): this one is about a *deserialize* failure of an already-compiled artifact and is stable at 87; that one is about *when* the loading fee is charged and is still nightly.
- **`FixContractLoadingCost`** — **nightly only, PV 129** (`core/primitives-core/src/version.rs:632`; `core/parameters/res/runtime_configs/129.yaml`); **not active at 87**. When enabled, `fix_contract_loading_cost` moves the loading fee from `after_loading_executable` to `before_loading_executable` (`gas_counter.rs:247`/`:264`) and makes `abort_but_nop_outcome_in_old_protocol` produce a real `abort` instead of a zero-gas `nop_outcome` (`runtime/near-vm-runner/src/logic/logic.rs:266`). On stable it is `false`, so the fee is charged post-load and method-resolve failures return NOP outcomes.
- **`UniversalAccounts`** — activates **PV 87** (`version.rs:629`); new this release. Sets `Config::universal_accounts` (`87.yaml:42`), which gates the `universal_state_init_to_account_id` and `promise_batch_action_universal_state_init` imports (`runtime/near-vm-runner/src/imports.rs:216`/`:221`).
- **`EnforcePerReceiptStorageProofLimit`** — activates **PV 86** (`version.rs:618`). The runtime seeds `storage_proof_size_before_receipt` only when enabled (`runtime/runtime/src/lib.rs:925`); `RecordedStorageCounter` then enforces `per_receipt_storage_proof_size_limit` (4 MB since PV 69), raising `HostError::RecordedStorageExceeded`. `EnforceStorageProofLimitForAllActions` (PV 87, `version.rs:624`) extends the same bound past `FunctionCall` to all action kinds — that part is runtime-side, see [runtime-execution](runtime-execution.md).
- **`FixMlDsaCostCharging`** — activates **PV 87** (`version.rs:627`). Sets `Config::fix_ml_dsa_cost_charging` (`87.yaml:35`), which inside the VM changes only gas-key pricing: `gas_key_exec_pk_len` (`runtime/near-vm-runner/src/logic/logic.rs:194`) prices the exec (storage) fee on `PublicKey::trie_id_len()` rather than the wire length. The meta-transaction half is runtime-side.
- **`YieldWithId`** — activates **PV 85** (`version.rs:612`). Sets `yield_with_id_host_fns` (`85.yaml:5`), enabling `promise_yield_create_with_id` / `promise_yield_resume_with_yield_id`.
- **`GlobalContractSameChunkCallFix`** — activates **PV 87** (`core/primitives-core/src/version.rs:628`). Runtime-side, but it decides what this component sees: applying a `DeployGlobalContract` now also calls `state_update.record_global_contract_deploy` (`runtime/runtime/src/global_contracts.rs:219`–`:225`), so a `FunctionCall` in the *same chunk* as the deploy can resolve the code. Before 87 that call found no code and `contract.get_code()` returned `None`, i.e. `VMRunnerError::ContractCodeNotPresent` (`runtime/near-vm-runner/src/wasmtime_runner/mod.rs:723`). See [runtime-execution](runtime-execution.md).
- **`RejectEmptyMethodName`** — activates **PV 87** (`version.rs:620`). `validate_function_call_action` rejects an empty `method_name` on *newly created* receipts (`runtime/runtime/src/action_validation.rs:321`–`:326`, `ValidateReceiptMode::NewReceipt`). The VM's own empty-name check in `before_loading_executable` (`gas_counter.rs:243` — `MethodResolveError::MethodEmptyName`) is unchanged and still runs; from 87 it is only reachable for receipts that were already in flight. See [runtime-execution](runtime-execution.md).
- **`_DeprecatedWasmtime`** — activated at **PV 84** (`version.rs:600`) and renamed to `_Deprecated*` this release because 84 is now `MIN_SUPPORTED_PROTOCOL_VERSION`. Its effect (`vm_kind: NearVm → Wasmtime`, plus `reftypes_bulk_memory`) is therefore **unconditional**; the NearVM backend it used to switch away from no longer exists in the tree. Any claim that a node can select a non-Wasmtime backend is false at this release.
- **Compute costs (NEP-455)** — long stabilized (`_DeprecatedComputeCosts`, PV 61, `version.rs:548`). `compute_usage` is computed independently of gas in `compute_outcome` (`runtime/near-vm-runner/src/logic/logic.rs:116`).
- Also stable and below `MIN_SUPPORTED`: `_DeprecatedGlobalContracts` (`global_contract_host_fns`), `_DeprecatedEthImplicitGlobalContract`, `GasKeys`/`PostQuantumSignatures` (PV 85, `gas_key_host_fns`, ML-DSA keys), `_DeprecatedAltBn128`, `_DeprecatedBLS12381`.

### Not protocol-gated (unconditional this release)

- **NearVM removal** (#15988, #15989), **`prepare_v2` removal** (#16355), **old-wasmparser removal** (#16052), **`VMLogic` removal** (#16322), **preparation fuzzer removal** (#16362). These are code-level; they do not change consensus behavior at any supported version because the removed paths were already unreachable at PV ≥ 84.
- **`revert(runtime): panic again on vm nondeterministic and unknown errors`** (#16186). `VMRunnerError::Nondeterministic` and `VMRunnerError::WasmUnknownError` are restored as `VMRunnerError` variants (`runtime/near-vm-runner/src/logic/errors.rs:29`, `:31`) and the runtime `panic!`s on both (`runtime/runtime/src/function_call.rs:334`, `:337`) rather than committing a `Failure` outcome with `gas_burnt: 0`. The commit message explicitly declines to gate this by protocol version, on the grounds that the condition should be unreachable and that committing a non-deterministic outcome is worse than a crash.
- **Explicit instance metadata limit** (#16024): `max_core_instance_size(1 MiB)` on the pooling allocator (`wasmtime_runner/mod.rs:73`, `:494`). Same value on every node, so it is deterministic; a module needing more metadata fails to instantiate and surfaces as a graceful `FunctionCallError`.
- **`neard` panics for a mainnet/testnet validator on non-x86_64** (#15919, `neard/src/cli.rs:392`). VM-determinism related: the wasmtime strategy is `Winch` on x86_64 and `Cranelift` elsewhere (`wasmtime_runner/mod.rs:520`), so a non-x86_64 validator runs a different code generator and risks diverging.

## Invariants & failure modes

- **Determinism.** Gas values and the outcome (including a guest error) must be identical across validators; a `VMRunnerError` signals node-local corruption and must crash rather than diverge (`runtime/near-vm-runner/src/runner.rs:10`–`:25` doc, `runtime/near-vm-runner/src/logic/errors.rs:12`).
- **Graceful guest errors vs. runner errors.** `FunctionCallError` (`errors.rs:45`) — `CompilationError`, `LinkError`, `MethodResolveError`, `WasmTrap`, `HostError`, `LoadingError` — becomes `VMOutcome.aborted` and is committed on-chain. Note it **no longer has a `WasmUnknownError` variant** (removed by #16186). `VMRunnerError` (`errors.rs:12`) — `InconsistentStateError`, `CacheError`, `LoadingError`, `ExternalError`, `Nondeterministic`, `WasmUnknownError`, `ContractCodeNotPresent` — propagates as `Err` from `run`, and the runtime maps it to a storage error, a nop outcome, or a panic.
- **Gas limits.** Never burn more than `min(prepaid_gas, max_gas_burnt)`; enforced in `burn_gas`/`process_gas_limit` (`gas_counter.rs:159`/`:179`). Out-of-gas ⇒ `GasLimitExceeded` / `GasExceeded`. In view mode `prepaid_gas` is `max_gas_burnt`, so a view call cannot exceed `max_gas_burnt_view` even in pure wasm (`gas_counter.rs:101`).
- **View-mode restrictions.** State-mutating and private host fns return `HostError::ProhibitedInView` (e.g. `storage_write` `wasmtime_runner/logic.rs:4868`, every promise fn).
- **Limit enforcement.** `NumberPromisesExceeded` (`wasmtime_runner/logic.rs:520`), `KeyLengthExceeded`/`ValueLengthExceeded` (`:4879`/`:4893`), `NumberOfLogsExceeded` (`logic/logic.rs:77`), `TotalLogLengthExceeded` (`logic/logic.rs:98`), `RecordedStorageExceeded` (`recorded_storage_counter.rs:27`), plus the whole `PrepareError` family at preparation time (`errors.rs:163`).
- **Balance.** `deduct_balance` errors with `BalanceExceeded` (`logic/logic.rs:70`); `ExecutionResultState::new` panics if the starting balance overflows `u128` (`:49`) — a should-never-happen invariant guaranteed by the runtime, which pre-checks it (`runtime/runtime/src/function_call.rs:49`).
- **Preparation defense-in-depth.** `CompilationError::WasmtimeCompileError` (`errors.rs:138`) is emitted when the backend rejects a module our own preparation pass should have caught; it is a graceful abort, not a crash.
- **Host errors survive the wasmtime boundary.** Every host error is boxed in an `ErrorContainer` (`wasmtime_runner/mod.rs:1113`) and taken back out by value in `IntoVMError` (`:376`); taking it twice `panic!`s, which asserts the one-error-per-trap invariant.
- **Cache poisoning is bounded.** A compile failure, a missing `memory` export, a link failure, and (at PV ≥ 87) a deserialize failure are all cached as `FunctionCallError`s keyed by the same `ContractCacheKey`, so a bad contract is diagnosed once and replayed identically, rather than recompiled every call.

## Open questions

- The exact per-check ordering inside `prepare_v3` when several limits are violated at once follows wasm section order (types → tables → globals → functions → code), but the interaction with `finite_wasm` analysis errors (which all collapse to `Deserialization`/`Serialization`) was not exhaustively traced; `instrument_v3.rs` was read only for its error mapping.
- `max_globals_per_contract` (#16047) ships as enforced code but is only set in `157.yaml` (nightly); `bls12381_not_in_group_fix` likewise only in `155.yaml`. Whether the globals cap is intended to reach a stable version before nightly reaches 157 could not be determined from the tree.
- `VMKind::replace_with_wasmtime_if_unsupported` and the `Wasmer0`/`Wasmer2`/`NearVm` enum variants are retained "because `VMKind` is part of a serialization protocol" (`core/parameters/src/vm.rs:9`), and nothing at a supported protocol version can produce those values. They are still load-bearing in one place: `VMKind` derives `BorshSerialize` (`core/parameters/src/vm.rs:20`) and is a field of `ContractCacheKey::Version5`, which is borsh-hashed into the on-disk cache key — so removing a variant would renumber `Wasmtime` from 1 and invalidate every cached artifact. Whether any other persisted artifact depends on the ordinals was not established.
- The `vm_hash` `version` constant (73) is bumped by hand when artifact compatibility changes; there is no automated check that it was bumped, so a missed bump would silently reuse incompatible cached artifacts. Whether CI covers this was not determined.
